Armin Ronacher created Flask and Jinja and spent a decade at Sentry before co-founding Earendil in Vienna, which shepherds the minimalist Pi coding agent with Mario Zechner. Consolidated learnings

  • Keep the agent harness minimal—four tools (Read, Write, Edit, Bash) and a short system prompt—and let the agent extend itself with custom skills and TUI tools instead of loading heavy MCP servers.
  • Expect model upgrades to change how your harness behaves even when the harness itself does not change: corrections drop, runs grow longer, and models reach for Bash more often.
  • Push back against overly defensive AI code. Agents see local failures and pile on fallbacks; good engineering makes bad states unrepresentable by upholding global invariants.
  • Use autonomous loops where verification is mechanical or shelf life is short (porting libraries, benchmarking, research), not blindly on core architecture you need to comprehend long-term.
  • Keep comprehension checkpoints inside longer agent runs: ask the agent for a short executive summary in readable HTML before verification so you can redirect bad tradeoffs early.
  • Starting repos is now cheap, but human attention is fixed. Resist unnecessary forks and uncontrolled growth ('Wildwuchs') where shared standards and upstream collaboration matter.
  • Long-running and overnight agent tasks need durable, checkpointed runtimes that can suspend and resume cleanly across crashes and flex-scheduled inference pauses.

Pi extends itself with custom TUI tools and zero MCP

  • built a feature
  • 4 core tools; /answer, /todos, /review built by Pi

Rather than installing community plugins or MCP servers, Ronacher tells Pi—which ships with only Read, Write, Edit and Bash—to write, hot-reload and maintain its own terminal extensions and skills to his exact specifications.

Details
  • Pi built his /answer dialog (reformatting prose questions into an input box), /todos markdown tracker, /review branching code-review flow, and /files picker.
  • He replaced all browser-automation CLIs and MCPs with a single CDP skill written and maintained by the agent itself.
  • Tree-structured sessions let him branch into a side quest to fix a broken tool or run a fresh review context, then rewind and summarize back into the main branch.
  • He throws skills away as easily as he creates them, treating custom tooling as malleable clay.

Parallel Pi sessions triage a flood of external issues and PRs

  • solved a problem
  • 3,145 external items in 90 days; 8% of auto-closed PRs merged

Using Pi to build Pi, Earendil auto-closes issues and PRs from unapproved contributors and runs parallel Pi windows with custom /is and /wr commands to independently reproduce bugs without trusting AI-generated issue diagnoses.

Details
  • Over 90 days Pi's repo received 3,145 external issues and PRs (excluding Earendil staff); 2,504 were auto-closed, 26% of issues were eventually reopened or fixed, and only 60 of 714 auto-closed PRs (~8%) were merged.
  • Their /is command explicitly tells Pi not to trust the contributor's LLM-written root-cause guess and to verify behavior directly from source code.
  • A custom prompt-url-widget renames each Pi terminal window with the GitHub issue title and author so several investigations can run in parallel, followed by /wr to update the changelog, commit, and close the issue.

Earendil ships Pi 1.0 and Pi Durable for crash-safe agents

  • launched something
  • Checkpointed turns and tool calls survive process restarts

On October 1, 2026, Earendil released Pi 1.0 alongside Pi Durable, an experimental TypeScript runtime that checkpoints every model turn and tool call so long-running agents survive crashes and inference pauses.

Details
  • Designed for overnight and flex-scheduled agent tasks where a 2-minute manual restart habit no longer works.
  • Every model request and tool invocation writes a checkpoint so a new process can reopen storage and resume from the last completed boundary.
  • Lets operators suspend idle sandboxes while waiting on cheaper flex-scheduled tokens.

Same four-tool harness jumps from 2.5-minute to 14-minute task runs

  • moved a metric
  • P90 task runtime: ~2.5 min (Dec 2025) to 14+ min (Nov 2026)

Analyzing a year of his own Pi JSONL session logs, Ronacher showed that 90th-percentile autonomous task duration climbed nearly sixfold—while corrections and aborts fell—with virtually no change to Pi's four-tool harness.

Details
  • Data filtered to his default Pi setup across model generations from late 2025 through late 2026.
  • Models also shifted toward invoking Bash far more than dedicated file tools, and made plugins like Pi Auto Research redundant.
  • His daily prompt count stayed roughly flat (~120 to 190 prompts/day), while total agent active time grew from less than a workday to multiples of his workday.

141 agent-started repos reveal that human attention is the ceiling

  • solved a problem
  • 141 repos started vs. ~10-15 kept active past 5 days

Plotting his own Git repositories over the year, Ronacher found he had started 141 projects with coding agents, yet only about 10 to 15 held his attention for more than five days of commits.

Details
  • An informal survey of peers showed the same pattern: agents make starting software trivial, not caring for it.
  • A friend who fully automated an open-source repo's issues and PRs still shut it down because he no longer cared enough to spend tokens on it.
  • Prompted Ronacher's 'workshop before factory' rule and his mid-run HTML summary checkpoint.

Interview notes

Armin Ronacher: The Software Atelier and Building Pi with Pi

Armin Ronacher (Flask creator, co-founder and CTO of Earendil) across his 2026 writings on lucumr.pocoo.org and his November 2026 talk The Software Atelier at AI Engineer CODE. He represents the craft-first practitioner wing: deeply bullish on coding agents, yet blunt about where they degrade codebases.

How he works with Pi

  • Uses Mario Zechner's minimalist Pi agent (four core tools: Read, Write, Edit, Bash; zero MCP) and asks Pi to build and hot-reload its own extensions and skills.
  • Runs parallel Pi terminal sessions to reproduce GitHub issues with /is (explicitly instructed to ignore AI-written guesses in the issue body) and closes them with /wr.
  • Asks the agent around 70% through long runs for a short typeset HTML executive summary so he can intervene before bad abstractions harden.

Key cautions

  • Models are "mortally terrified of exceptions" and pile on local fallbacks instead of enforcing global invariants; unattended loops amplify this tendency.
  • Uncontrolled growth (Wildwuchs): when everyone forks and regenerates formats with agents instead of collaborating upstream, interoperability breaks.
  • Cognitive dependency: teams risk building software "organisms" that nobody in the room can explain without asking an agent first.

Session metrics (P90 runtimes of ~2.5 to 14+ minutes, 120-190 prompts/day, 141 started repos vs. 10-15 maintained) come from Ronacher's own Pi logs and GitHub repos as presented at AI Engineer CODE 2026, not a controlled industry benchmark. Pi tracker counts (3,145 external items, 8% PR merge rate) reflect 90 days of public GitHub data from his May 2026 post. Earendil stewards Pi and Pi Durable, so his views on minimal harnesses reflect his own product bets.
