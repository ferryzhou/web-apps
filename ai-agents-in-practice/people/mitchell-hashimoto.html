Consolidated learnings

  • Drop the chatbot and use an agent with a loop (read files, execute programs, make HTTP requests); then force yourself through the awkward learning curve by reproducing your own manual commits with an agent.
  • Split vague work into separate planning and execution sessions, and know when NOT to reach for an agent.
  • Practice harness engineering: whenever an agent makes a mistake, add a rule to AGENTS.md or build a fast verification tool so it never makes that mistake again.
  • Use the last 30 minutes of the workday to kick off research, library comparisons, or issue-triage agents for a 'warm start' the next morning.
  • Turn off agent desktop notifications. Context switching is expensive; you should decide when to interrupt the agent during natural breaks, not the other way around.
  • Match review rigor to stakes: review every line (and require a 'whiteboard defense' of design decisions) on long-lived systems like Ghostty, and zero review on a throwaway site.
  • In open source, cheap AI code broke default trust. Require explicit human vouching (like Vouch) and ban drive-by unlinked PRs while keeping maintainers free to use agents responsibly.

Agent stories

Ghostty's AGENTS.md turns every repeated agent mistake into a harness rule

  • solved a problem
  • 39 lines (~404 tokens) eliminating recurring bad agent behaviors

In his February 5, 2026 essay naming 'harness engineering,' Hashimoto showed how Ghostty's compact AGENTS.md—paired with targeted build flags and test filters—encoded every recurring agent mistake into a permanent guardrail.

Details
  • Each line in Ghostty's 39-line AGENTS.md came directly from a real bad behavior (such as running slow full builds instead of -Demit-macos-app=false or -Dtest-filter).
  • Even includes a blunt anti-slop rule telling agents never to open GitHub issues or PRs on a user's behalf.
  • Combined with programmed helper scripts (screenshots, FreeBSD QEMU test VM, filtered tests) so agents verify their own work before he ever inspects it.

Vouch shifts open-source contributions from default trust to explicit vouching

  • launched something
  • Built after bad AI PRs grew 10x+ (2-3 low-quality PRs/day on Ghostty)

After bad contributions to Ghostty surged more than 10x, Hashimoto tightened Ghostty's AI policy in January 2026 and built Vouch—an open-source trust management tool and GitHub Action that requires maintainers to explicitly vouch for contributors.

Details
  • First prototyped in Ghostty PR #10559 and released standalone on February 7, 2026.
  • Unvouched users cannot flood the PR queue with drive-by agent submissions; maintainers vouch for contributors who show real understanding in issues or discussions.
  • Inspired in part by Mario Zechner's Pi trust workflow; Hashimoto explicitly exempted Ghostty maintainers so they can keep using AI agents daily.

End-of-day research and triage agents create a warm start every morning

  • solved a problem
  • Last 30 min/day queued; background agent active 10-20% of workday

To get net efficiency without babysitting agents during peak deep-work hours, Hashimoto blocks the last 30 minutes of each day to launch deep research, speculative prototypes, and GitHub CLI issue-triage reports.

Details
  • Triage agents are strictly read-only—never allowed to reply on GitHub—and produce morning reports pointing him to high-value or slam-dunk issues.
  • During the day he delegates one slam-dunk issue at a time to a slower, thoughtful model (such as GPT-5.2-Codex / Amp deep mode taking 30+ minutes) while he does deep manual work with notifications off.
  • Said the biggest benefit was choosing what to think about, while avoiding skill atrophy on the hard parts he still codes by hand.

AI prototypes Ghostty's macOS command palette and automatic updater

  • built a feature
  • Command palette shipped lightly modified from a screenshot prompt

Hashimoto's first 'oh wow' moment was pasting a screenshot of Zed's command palette into Gemini and getting working SwiftUI code back in seconds; he later shipped Ghostty's unobtrusive macOS auto-updater with full public agent transcripts.

Details
  • The macOS command palette shipped in Ghostty with only light edits from the initial generated code.
  • For the Sparkle-based macOS auto-updater, he designed the backend architecture first, used agents to prototype the SwiftUI titlebar accessory UI outside his comfort zone, and then iterated by hand.
  • Demonstrated his rule: domain experts use agents to cross unfamiliar UI/language boundaries, then apply manual polish.

Superlogical launches Rex, a persistent terminal multiplexer wired for agents

  • launched something
  • OSC 7501 status protocol + rex CLI across Claude Code, Codex, OpenCode, Pi

In July 2026 Hashimoto co-founded Superlogical and opened beta testing in October for Rex, a native terminal multiplexer with a background session server, scriptable JSON CLI, and the OSC 7501 protocol so coding agents report their live state.

Details
  • Built on MIT-licensed libghostty while Ghostty itself remains an independent non-profit.
  • Deliberately ships no built-in AI chat assistant; instead, rex skill setup wires Claude Code, Codex, OpenCode and Pi into rex CLI commands (rex split, rex capture, rex run --wait) and OSC 7501 status (idle, working, blocked, done, errored).
  • Separates the UI from the background process server so closing the app never kills long-running agent sessions, with optional remote access via Tailscale.

Source: Mitchell Hashimoto blog, Jul 2026 & Rex beta coverage, Oct-Nov 2026 · Oct 5, 2026

libghostty 1.0 becomes the shared terminal engine for agentic tools

  • moved a metric
  • 100+ projects (Herdr, cmux, Neovim, OrbStack); ~1,500 lines of C

Shipped November 6, 2026, libghostty 1.0 lets developers build a full-featured native terminal in about 1,500 lines of C—becoming the foundation for a wave of 2026 coding-agent multiplexers and developer tools.

Details
  • Adopted by agentic terminal tools such as Herdr and cmux, alongside Neovim, Vercel's Turborepo, OrbStack, devenv, Antithesis and a WASM build (ghostty-web).
  • Community bindings span Rust, Go, JavaScript, Swift, Python, .NET, Elixir, Dart and Java, with over 100 projects listed on awesome-libghostty.
  • Hashimoto notes far more people now use a terminal powered by libghostty than use the Ghostty app itself.

Interview notes

Mitchell Hashimoto: Harness Engineering, Vouch, and Building Rex

Mitchell Hashimoto (HashiCorp co-founder, Ghostty creator, Superlogical co-founder) across his landmark February 5 essay My AI Adoption Journey, The Pragmatic Engineer (Feb 2026), Fragmented #310 (Apr 2026), and his late-2026 Superlogical / Rex and libghostty 1.0 launches.

His 6-step adoption ladder

  1. Drop the chatbot; use an agent that reads files, runs programs and makes HTTP calls.
  2. Reproduce your own manual commits with an agent until you learn its real boundaries.
  3. Spend the last 30 minutes of each day launching research, exploration and read-only triage agents.
  4. Outsource slam-dunk tasks one at a time while doing deep manual work—with notifications turned off.
  5. Engineer the harness: every repeated mistake becomes a line in AGENTS.md or a fast verification script.
  6. Aim to always have one background agent running usefully alongside your own thinking.

Open-source & infrastructure bets

  • Built Vouch after AI slop PRs grew 10x+ on Ghostty; later announced Ghostty was leaving GitHub over reliability issues.
  • Co-founded Superlogical to build Rex, a persistent multiplexer with the open OSC 7501 protocol so coding agents can report when they are working, blocked or finished without baking an AI chat sidebar into the terminal.
