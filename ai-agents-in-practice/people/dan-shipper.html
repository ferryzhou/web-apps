Co-founder and CEO · Every

Dan Shipper

Dan Shipper runs Every, a roughly 30-person media and software company with several AI products, a consulting arm and agents in almost every workflow. In 2026 Every went from giving each employee a personal OpenClaw agent to one shared company agent in Slack, and he argues that every agent still needs a human who cares for it.

Claudie, an AI project manager, runs consulting ops

  • solved a problem
  • About 15 hours a week saved

Every built Claudie in Claude Code to keep the consulting team's client status dashboard current. Every says she saves the team about 15 hours a week, after several earlier versions had to be scrapped.

Details
  • Problem: the head of consulting spent hours pulling updates from email, Docs, Sheets, meeting transcripts and her calendar into a dashboard.
  • Claudie gathers that information and updates the dashboard so nothing falls through the cracks.
  • An AI engineer spends much of his time in Slack correcting and improving the agent.
  • Earlier iterations were 'fired' because they were not structured right; onboarding was harder than hiring a human.
  • Every was trialing two more agents (sales pipeline and visual design) for the same team.

Users' agents file bugs, agents fix them

  • solved a problem

For Proof and other Every products, users' agents send bug reports with exact repro steps and a guess at the cause. Each becomes a GitHub issue that Every can hand to an agent to fix.

Details
  • Proof is open source, so a user's agent can point to where in the code it thinks the bug is.
  • The report becomes a GitHub issue, and an agent is sent off to fix it.
  • Inside Every, Dan's agent R2-C2 took bug reports and feature requests for Proof, so colleagues stopped tagging Dan.
  • Dan says this does not work for everything, but agent bug reports are better than human ones.

Source: Lenny's Podcast, May 2026, ~30:07-30:46; AI & I, Apr 2026, ~00:15:00 · May 2026

Quarterly planning run through Notion agents

  • solved a problem
  • A plan for every team, drafted from agent interviews

For planning at the end of 2025, every employee talked to a Notion agent that asked about last year, goals and metrics, pushed back, and tied answers to company strategy. Dan got a drafted plan for each team.

Details
  • Setup: one Notion agent plus a top-level company strategy document.
  • The agent interviewed each person about results, goals and metrics, and pushed back on weak answers.
  • It produced strategy reports and quarterly plans for each part of each team.
  • Dan then reviewed them for quality and to spot teams that needed to talk to each other.

Vibe-coded Proof broke at launch, then got rebuilt

  • launched something
  • Thousands of documents in 48 hours; stabilized in a couple of days

Dan vibe-coded Proof, an agent-native document editor, and launched it free. Heavy use broke it repeatedly until outside experts reviewed it and an engineer rebuilt the core with Codex.

Details
  • Thousands of documents were created in the first 48 hours and the site kept going down.
  • Dan says Codex skipped collaboration best practices, and one-off bug fixes piled up complexity.
  • Outside experts reviewed the repo; an engineer rebuilt the architecture with Codex in a couple of days.
  • Lesson he drew: add a planning step where the agent researches best practices before coding.

Source: The Neuron, Mar 2026, ~27:12-36:44 · Mar 2026

From a personal agent each to one shared Every Agent

  • launched something
  • Token costs cut more than 80% across 11 common tasks

Every gave each employee a hosted OpenClaw agent (Plus One) in early 2026, found they were hard to maintain and mostly died off, and in October launched one shared company agent in Slack. A later model upgrade and small fixes cut its token costs by more than 80% on 11 common tasks.

Details
  • Plus One agents worked well for some roles, such as the growth lead's agent, but many needed constant upkeep.
  • Dan noticed people learned most by watching someone else's agent work in public.
  • The Every Agent works in public Slack threads and can save a working workflow as a skill anyone can run.
  • Every moved hosting to Claude Managed Agents to stop maintaining servers.
  • Routing tasks to a cheaper model raised costs; a model upgrade plus code fixes lowered them.

Source: Every, Context Window, Oct 2026; AI & I, Apr 2026 · Oct 2026

Key learnings

  • Give every agent an owner who watches its work and maintains it; agents left alone stop being useful.
  • Start with one shared company agent run by a forward-deployed builder, not a personal agent for everyone. He changed his view here: in April he championed personal agents, by May he had 'completely flipped', and in October Every replaced them with one shared agent.
  • Have agents work in public Slack channels so others can see what they can do and learn to trust them.
  • Make the agent plan and research best practices before it writes code; most of the work is in planning.
  • Avoid stacking one-off agent fixes; have someone act as architect for a few hours a week to keep the core stable.
  • Build review rules into the repo so agent PRs are checked before a human reviews them.
  • Expect automation to create new human work, such as agent caretakers, and plan hiring for it.
  • Adopt each new model quickly and build products on its new capabilities.

Interview notes

Dan Shipper: One Agent for the Whole Company

Every CEO Dan Shipper on Lenny's Podcast (May 2026). Every has about 30 people running about 6 software products. The team doubled in a year even as agents took on more work.

How Every uses agents

  • "We have an agent internally called Claudie, which runs our whole consulting practice."
  • He now favors one "super agent" for the whole company over a personal agent for each person.
  • Quarterly planning ran through agents that interviewed every employee and drafted the team plans.
  • Users' agents file detailed bug reports. Those become GitHub issues, and agents fix them.
  • Engineers mostly work in plain language and rarely read code line by line.

Lessons

  • "Agents need people who care about them." Someone has to maintain and improve each agent.
  • More automation brought more hiring, not less.
  • Benchmarks measure only what can be scored. People still decide what's worth building.
  • Caveat: much of the episode is predictions rather than practice.

Numbers such as 15 hours a week saved, the 80% cost cut and the headcount growth are Every's own claims; Every sells agents and consulting, so these stories double as marketing.
