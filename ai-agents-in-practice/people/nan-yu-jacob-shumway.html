Nan Yu & Jacob Shumway

Nan Yu leads product at Linear, the issue-tracking company, and Jacob Shumway co-built Linear Agent with him; it launched in public beta on March 24, 2026. Their agent turns conversations in Slack, notes and support tickets into tracked issues and code changes, and Linear says it now resolves about 30% of its own incoming bug reports this way.

Latest view (Aug 9, 2026): As of August 2026, Nan and Jacob argue for agents with minimal instructions, tools to fetch their own context and skills loaded on demand, anchored on the one workflow most users need and with a human kept accountable.

Consolidated learnings

  • Map the real workflow first: where work starts, where context lives and what done means, then put the agent there (e.g., Slack), not in a separate chatbot.
  • Give the agent tools to fetch context and skills it loads on demand, not a big prompt or every action at once. Over-prompting usually makes it worse.
  • Launch quietly to one frequent job, watch real usage, and make those hot paths rock solid while accepting variance elsewhere.
  • Prototype with the biggest model until it works, then write evals and move narrow jobs to smaller models.
  • Turn feedback and failures into evals and backlog issues automatically, and only add evals where consistency matters.
  • Keep a human accountable: the person who delegates stays the assignee and reviews the output.
  • Their view shifted: in 2025 Nan framed Linear mainly as a home for third-party agents; by 2026 they built a native agent and argued for minimal instructions and tools over context.

Agent stories

Stealth Slack launch found the main use case

  • launched something
  • About 80% of early requests were issue creation

Linear quietly turned the agent on for internal users through Slack mentions. Most people used it to turn messy notes and threads into issues, so the team optimized hard for that path.

Details
  • Setup: a hacky prototype that called an LLM from the frontend and used Linear's command menu actions as tools.
  • What the agent did: read pasted sales call notes or Slack threads and extracted the bugs and feature requests as issues.
  • Humans' role: the team watched usage and thumbs up/down feedback, then added a router that sent about 80% of requests to a sub-prompt tuned for issue creation.
  • Result: issue creation became the 'hot path' they polished first; other uses like translating French Intercom tickets appeared on their own.

Slack debate became an issue and a PR in 6 minutes

  • built a feature
  • 6 minutes from Slack thread to pull request

Nan, a designer and Jacob debated a UI change in Slack, then told Linear to 'just do it'. The agent wrote the issue from the thread, assigned it to Jacob and produced a PR in about six minutes.

Details
  • Setup: Linear Agent in Slack with access to the thread, the codebase, the project and other issues.
  • What the agent did: inferred the decision from the conversation, filed the issue in the right project and opened a PR.
  • Humans' role: Jacob stays the assignee and reviews the PR; a human owns the decision.
  • Result: a testable change in about 6 minutes, with the work tracked in Jacob's backlog instead of lost in Slack.

Skills replaced 'expose every tool' to cut hallucinations

  • solved a problem

Exposing every backend action as a tool confused the agent and caused hallucinations. The team moved to skills that the agent loads only when a request needs them, and the agent now reports gaps it cannot handle.

Details
  • Setup: early versions had access to many actions but were not good at most of them.
  • What changed: a tool lets the agent load intent-specific skills (tools plus instructions) on demand, keeping context small.
  • Humans' role: when the agent lacks a capability it reports it, which creates a steady stream of backlog issues and new evals.
  • Result: Jacob says the skills setup 'unlocked a lot of things'; Linear's Aug 2026 engineering post describes the same design.

Interview notes

Linear: 5 Rules for AI Agents That Work in Production

Nan Yu and Jacob Shumway, who built Linear Agent, on Peter Yang's Behind the Craft (Aug 2026). Their main point: "The models are really smart, but we're just not using them enough." Over-prompting usually makes an agent worse.

The 5 rules

  1. Map the real workflow first. Know where work starts, where the context lives, and what "done" means. Hook into those places. If work starts in Slack, start the agent in Slack, not in a separate chatbot.
  2. Give it tools, not context. "Give it as little instruction as possible. Give it the tools to load context." Their fix for hallucinations was skills the agent loads only when it needs them, instead of exposing every action at once.
  3. Start with one frequent job. Theirs was turning sales notes and Slack threads into issues. They launched it quietly and built the next steps from real usage.
  4. Use the biggest model until it works. Write evals, then move to smaller models for narrow jobs.
  5. Turn real failures into evals. When the agent lacks a capability, it reports the gap, and the gap becomes an issue automatically.

Other lessons

  • Make a few showcase use cases rock solid. Accept more variance in the rest.
  • Use evals only where consistency matters. Too many give false signals.
  • Don't lock it down. Users will find uses you didn't plan for, like translating French support tickets.
  • Demo: a Slack debate became an issue and then a PR in 6 minutes.
