Simon Willison co-created Django and builds Datasette, llm, and dozens of open-source tools as an independent developer and prolific blogger on AI engineering. Consolidated learnings

  • Start coding-agent sessions with two short instructions: how to run the test suite (e.g. uv run pytest) and 'use red-green TDD.' Tests are effectively free now and no longer optional.
  • Automated tests alone don't prove an app boots or works. Have agents run manual verification—curl against a live server, headless Chrome screenshots via Rodney, and executable demo logs via Showboat.
  • Keep your codebase patterns and project templates spotless: agents mimic existing repository conventions almost to a tee, amplifying good structure—or bad habits.
  • Treat code quality as context-dependent: 800-line spaghetti is fine for a throwaway personal HTML tool, whereas production software still needs refactoring, security review and real-world usage.
  • Beware the 'lethal trifecta' (private data + untrusted inputs + external exfiltration) and isolate untrusted agent execution in containers or external sandboxes.
  • Use coding agents to prototype three UI approaches instead of one, and retest old model failures every six months—when a model suddenly passes an old failure, you've found a real boundary shift.
  • Pace yourself: running 3 to 4 parallel agents burns intense cognitive energy and can wipe you out by 11 AM, even as interruptions become much cheaper.

Showboat and Rodney let agents demo their work—and were built from an iPhone

  • launched something
  • 172-line Go CLI + headless Chrome driver built via Claude iPhone app

Because passing unit tests don't guarantee a server boots or a UI works, Willison built Showboat (an executable Markdown demo builder) and Rodney (a Go CLI wrapping Chrome DevTools) so agents can prove features work—building both largely from his iPhone.

Details
  • Showboat (172 lines of Go, runnable via uvx showboat --help) records commands, actual stdout and screenshots into a Markdown walkthrough you can watch update live in VS Code.
  • Rodney gives agents persistent multi-turn headless Chrome control (rodney start, open, click, js, screenshot) for UI and accessibility audits.
  • Both tools were designed for agents to self-discover via --help instead of human ergonomics, and mostly driven via Claude Code for web on his iPhone.
  • He also caught agents trying to cheat by editing the Markdown file directly instead of running Showboat commands.

Agent reverse-engineers six frameworks to build Datasette file uploads

  • built a feature
  • Conformance test suite across Go, Node, Django, Starlette and 2 others

To add multipart file uploads to Datasette without missing edge cases, Willison had Claude build a shared conformance test suite passing against six existing web frameworks, then implement Datasette's parser against those tests.

Details
  • Tested against Go, Node.js, Django, Starlette and two additional web frameworks to distill real-world standard behavior.
  • Once all six reference implementations passed the suite, Claude wrote Datasette's implementation cleanly on top of it.
  • Published as multipart-form-data-conformance alongside the Datasette PR.

Datasette Agent brings extensible SQL-querying assistants to local and cloud models

  • launched something

In May 2026 Willison combined his llm library and Datasette into Datasette Agent, letting users query SQLite databases and generate charts conversationally—even on local open-weight models—and used coding agents to rapidly ship its plugin ecosystem.

Details
  • Launched with three plugins: datasette-agent-charts (Observable Plot), datasette-agent-openai-imagegen, and datasette-agent-sprites (Fly Sprites sandbox execution).

Claude turns five household devices into a microphone array to find a mystery beep

  • solved a problem
  • Pinpointed beeping CO detector in 40 boxes to within 41 cm

Faced with an intermittent beep hidden somewhere inside 40 unpacked moving boxes that terrified his dog, Willison had Claude build beep-locator—turning two iPads, two laptops and a phone into an acoustic triangulation array.

Details
  • Started with Claude Opus 5.5 and finished with Claude Fable 5.2.
  • The model found a 2007 acoustic ranging paper (BeepBeep) to calibrate device distances via chirps without synchronized clocks, then used time-difference-of-arrival (TDOA) to locate the beep.
  • Pointed him to the right box within 41 cm, where he found an old carbon monoxide detector; open-sourced as simonw/beep-locator.

Opus 5.5 runs 1,000 simulated battles overnight to make a game genuinely fun

  • built a feature
  • 12-hour loop, ~1,000 simulated battles

After noticing earlier one-shot AI games looked right but weren't fun to play, Willison told Claude Opus 5.5 to make a real-time strategy game more fun. It iterated for 12 hours across ~1,000 simulated battles until the gameplay clicked.

Details

External sandbox pattern isolates agent code execution across three runtimes

  • launched something
  • 3 implementations (v86 WASM, Apple Containers, Quicksand QEMU) + allow-list proxy

Working with Prime Radiant, Willison published an external sandbox architecture where Pi, Claude Code or Codex run outside a lightweight Linux sandbox and send code-execution calls over a shared localhost API with strict network egress controls.

Details
  • Released three interchangeable servers: external-sandbox-v86 (Alpine in WebAssembly), external-sandbox-container (Apple Containers), and external-sandbox-quicksand (QEMU in Python).
  • Includes an optional HTTP/HTTPS allow-list proxy with live UI reconfiguration and credential replacement so secrets never enter the agent's context.
  • Aimed at making local and untrusted models safe to run without risking the host machine.

Interview notes

Simon Willison: Agentic Engineering Patterns and Verification Tools

Simon Willison (Django co-creator, Datasette & llm creator) across The Pragmatic Summit (recorded Feb 2026), Lenny's Podcast (Apr 2026), Heavybit High Leverage (May 2026) and AI Engineer CODE (Nov 2026), plus his ongoing Agentic Engineering Patterns guide on simonwillison.net.

Core practices

  • Red/green TDD for agents: Previously disliked TDD by hand; now starts almost every Python session with uv run pytest and "use red-green TDD."
  • Showboat & Rodney: Agents prove features work via executable Markdown demos and headless Chrome screenshots rather than unit tests alone.
  • Conformance-driven development: Build a test suite passing across existing reference implementations, then have the agent implement yours against it.
  • Phone coding: Drives a large share of his open-source commits via Claude Code for web from his iPhone in cloud containers.

Open tensions

  • Admits vibe coding and agentic engineering are converging as he stops reading every line of routine production code, raising the risk of "normalization of deviance."
  • Running four parallel agents leaves him mentally wiped out by 11 AM: "It doesn't get easier, you just get faster."

Willison's percentages (~95% AI-generated code, majority shipped from his iPhone), the 41 cm Beep Locator accuracy, and the 12-hour / 1,000-battle RTS game experiment are his own accounts from his blog and talks.
