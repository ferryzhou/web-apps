David Heinemeier Hansson (DHH)

David Heinemeier Hansson (DHH) created Ruby on Rails and co-founded 37signals (Basecamp, HEY). After insisting in mid-2025 that he typed all his code by hand, Claude Opus 4.5 flipped his workflow: in 2026 he went 'pencils down' at 37signals, shipped Omarchy Quattro as an agent-first Linux desktop written entirely by agents, and argued that taste and the last 2% are the only moat left.

Latest view (Nov 20, 2026): As of November 2026 he says there is 'no moat in source code,' argues that Linux's terminal, config files and blunt errors make it the native OS for coding agents, and works 16-hour days obsessing over the final 2% of Omarchy while noting that legacy commercial codebases like Basecamp still resist hands-off delegation.

Consolidated learnings · Timeline · Agent stories

Consolidated learnings

  • Describe outcomes, not implementation steps. Experienced programmers can be worse at agentic engineering at first because they act like 'pointy-haired bosses' prescribing the how instead of letting the agent explore.
  • Expect very different results on greenfield vs. legacy codebases: agents wrote 100% of Omarchy Quattro cleanly, whereas 20 to 30 individually reasonable agent PRs on Basecamp 5 left the overall architecture in poor shape.
  • Expose a CLI for your app ('bring your own agent') instead of bolting an isolated chatbot onto every SaaS product.
  • Conventions and clear structure (like Rails' Convention over Configuration) help coding agents navigate repositories with less wasted context.
  • Use agents as a first-pass sieve on open-source pull requests so maintainers spend human judgment only on survivors—and don't worry about hurt feelings when rejecting machine drafts.
  • When code becomes cheap, taste and obsessing over the final 2% of polish become the real differentiator—and watch out for the addictive pull of 16-hour days.
  • Linux's historic drawbacks—terminal-first workflows, plain text config files and blunt error messages—are exactly the traits coding agents work best with.

Agent stories

Agents write 100% of Omarchy Quattro, an agent-native Linux desktop

  • launched something
  • 100% agent-written shipped code; 9 agent CLIs wired in; 104 QML files

Omarchy 4 (Quattro), released August 14, 2026, rewrote its entire Arch/Hyprland desktop shell in Quickshell and treated coding agents as first-class OS citizens. DHH says agents wrote 100% of the shipped code.

Details
  • Replaced eight separate desktop utilities (Waybar, Walker, Mako, SwayOSD, hyprlock, hypridle, swaybg, polkit-gnome) with one Quickshell process across 104 QML files (~1.2 MB) under 300 MB RAM.
  • Pre-wires nine coding-agent CLIs (Claude Code, Codex, OpenCode, Gemini CLI, Copilot CLI, Crush, Grok CLI, Pi, Oh My Pi), adds a top-bar token-usage panel, hands systemd crash core dumps straight to your agent, and bundles Herdr alongside tmux.
  • Ships an experimental ~/.claude/skills Omarchy skill so users can prompt their agent to reconfigure themes, hotkeys and desktop layout directly.

  • moved a metric

While many open-source maintainers fought off AI pull-request floods in 2026, DHH put agents in front of Omarchy's incoming PR stream to do preliminary review, merging more than 1,000 PRs in a single quarter.

Details
  • Agents filter, review and reject weak submissions before surviving PRs reach DHH's eyes.
  • He contrasts the emotional friction of rejecting human volunteer PRs with rejecting agent drafts: 'the clanker won't mind.'
  • Fifty-four first-time contributors landed changes in the Omarchy 4.0 release alone.

Basecamp 5 exposes how individually fine agent PRs can break architecture

  • solved a problem
  • 20 to 30 reasonable PRs still left architecture in poor shape

Unlike greenfield Omarchy, handing parts of Basecamp 5 over to agent-assisted pull requests hit an integration wall: 20 to 30 individually reasonable PRs from designers added up to an incoherent architecture that required substantial handwritten cleanup.

Details
  • Each PR passed local review on its own terms, yet lacked a unified mental model of a decade-old commercial codebase.
  • The shipped Basecamp 5 release combined agent work with significant human-written code.
  • DHH highlighted the gap between greenfield Omarchy and mature Basecamp/HEY as the clearest boundary on hands-off delegation in 2026.

Interview notes

DHH: From Hand-Coding Purist to Omarchy and 'Pencils Down'

David Heinemeier Hansson (Rails creator, 37signals CTO, Omarchy creator) across The Pragmatic Engineer (Apr 2026), Lex Fridman #501 (Aug 2026), his Rails World 2026 keynote (Sep 2026) and The a16z Show (Nov 2026). Few developers made a more public 180-degree turn between mid-2025 and late 2026.

What worked vs. what didn't

  • Greenfield triumph (Omarchy Quattro): 100% agent-written shipped code, Quickshell rewrite across 104 QML files, nine agent CLIs wired in, crash dumps routed straight to your agent, and 1,000+ community PRs pre-screened by agents in a quarter.
  • Legacy reality check (Basecamp 5): 20 to 30 individually sensible agent PRs from designers broke architectural coherence and needed heavy handwritten repair.
  • Product architecture: Expose CLIs for users' own agents rather than building mediocre in-app chatbots.

Core thesis

  • There is no longer a moat in source code; taste, curation and obsessing over the final 2% are what remain.
  • Linux's terminal, plain config files and blunt error messages make it the operating system agents naturally thrive on.

All productivity, user, fundraising and performance numbers (150K lines in August, 1,000+ PRs in a quarter, 99% CPU / 95% memory reduction on the experimental HEY Rust backend, ~$23M-$24M Omacom Foundation pledges, two-week Lightroom clone) are DHH's or Omarchy's own claims and were not independently audited. Note also the Rails Foundation / Evil Martians Stage 3 benchmark (Oct 2026), which found coding agents still missed production details like durable job queues and credential hygiene even when tests passed.
