Cowork went from build to launch in about 10 days

  • launched something

After seeing non-engineers bend Claude Code to non-coding work, a small team built Cowork. Boris says the build took about 10 days end to end and was fully written with Claude Code.

Claude found a memory leak faster than the expert

  • solved a problem

Boris was hunting a memory leak by hand with heap snapshots. A newer engineer simply asked Claude Code to find it, and Claude got there first.

Details
  • Setup: a memory leak in the Claude Code product.
  • Claude took a heap snapshot, wrote its own one-off analysis tool, found the cause, and opened a PR.
  • Human role: the engineer only described the problem and reviewed the fix.
  • Lesson Boris draws: give the agent tools to get context instead of feeding it context.

Automated review catches most bugs and writes lint rules

  • solved a problem
  • About 80% of bugs caught in CI review

Claude reviews every PR in CI and, by Boris's estimate, catches about 80% of bugs before a human does a second pass. He now asks Claude to write lint rules straight from review comments.

Details
  • Before: Boris logged review comments in a spreadsheet and wrote a lint rule once a pattern hit three or four instances.
  • Now: Claude runs code review in CI, and an engineer still does a second pass.
  • He asks Claude to write lint rules directly on coworkers' PRs.
  • Result: repeated feedback becomes an automatic check instead of a recurring comment.

Key learnings

  • Give the agent tools to fetch context, not a big upfront prompt.
  • Start most non-trivial tasks in plan mode, then let the agent execute. By mid-2026 he leaned more on sub-agents and auto mode, where a second Claude checks commands.
  • Use the most capable model at high effort for hard work; a cheaper model can burn more tokens on the same task. Drop effort only for simple tasks.
  • Staff projects lean and give people tokens without per-use approval. Optimize cost only after a use case scales.
  • Turn repeated review feedback into lint rules or checks, and have Claude write them.
  • Build for the model six months out, and avoid heavy scaffolding that the next model makes useless. Retest old failures on each new model.
  • Run several agents in parallel and move from prompting to supervising: loops that prompt Claude, and Claude managing other Claudes.
  • Hold engineering opinions loosely. He banned classes in Claude Code, then dropped the rule once models wrote them well.

Interview notes

Boris Cherny: Running Hundreds of Agents at Once

Boris Cherny, head of Claude Code at Anthropic, on Big Technology with Alex Kantrowitz (May 2026). Claude Code now writes 100% of Claude Code. Code written per engineer at Anthropic is up about 250% while quality has stayed stable. At Meta, by comparison, a 1 to 3% productivity gain in a year was hard-won.

How he works

  • He runs about 5 agents at a time on his laptop and hundreds overnight. "I have a Claude that's talking to my Claudes."
  • He hands off a task, works on something else, then reviews and corrects it. Once, he had Cowork check his email and calendar before booking 8 flights and 5 hotels, and it caught his own mistakes.
  • He keeps personal test cases and reruns them on every new model.
  • He picks the model and effort level per task: max effort for hard problems, low effort to save tokens.
  • He uses auto mode, where a second Claude checks each command, instead of clicking "always allow".

Advice for companies

  • Give everyone tokens without per-use approval, and make it safe to fail.
  • Big wins come from people you wouldn't predict, like an accountant or a new grad.
  • Optimize cost only after a use case scales.
  • Rebuild the process around AI. A computer at the edge of a paper office didn't help either.
  • Keep a beginner's mindset. What failed last month may work now.

All productivity numbers (150%, 200%, 250%, 80% of bugs caught, 10-day Cowork build) are Boris's own claims about Anthropic and were not independently verified; the number rose across interviews and the metric changed (productivity, merges, code per engineer).
